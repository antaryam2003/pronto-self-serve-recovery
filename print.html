Gap 01

The visit is a black box

There is no state between booked and done. At minute 3 and minute 45 the screen is identical, so the only way to learn anything is to ask a person.

Gap 02

The customer is the sensor

Nothing is flagged automatically. The customer must notice the delay, classify it, describe it, and then defend it — for failures the system can already see.

Gap 03

Support hours ≠ booking hours

Booking is sold as 24/7. Live chat runs roughly 7 AM – 10 PM. That leaves nine hours a day where you can book but cannot reach anyone when it fails.

Fix 01

The system is the sensor

Every transition is detected automatically and stamped. Nobody has to notice it's been 40 minutes. The delay credit lands before anyone asks for it.

Fix 02

Checkable, so resolvable

A no-show is a no-show because the GPS and timestamps say so — not because a customer describes it convincingly. That removes tickets rather than answering them faster.

Fix 03

A failure handled well builds trust

Visible, flagged, already refunding reads as "they're on top of this" rather than "they're unreliable." Same bad outcome, opposite feeling.
